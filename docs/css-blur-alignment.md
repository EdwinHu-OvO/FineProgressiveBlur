# CSS 模糊校准

## 半径与颜色

`maxRadius` 现在表示 CSS px 下的高斯标准差，与 `filter: blur(Npx)` 使用相同语义。
渐变模式默认使用 `σ(y) = maxRadius × (1 − smootherstep(y))`；传入 `blurCurve` 时改用 CSS `cubic-bezier(x1, y1, x2, y2)` 映射，固定半径图片仍使用全图相同的 σ。曲线的输入是从模糊外缘到正文接缝的归一化进度，输出会限制在有效半径范围内。

原实现使用 13 个旋转的 Vogel 圆盘采样点。圆盘的单轴标准差约为半径的一半；稀疏采样加逐像素旋转产生颗粒，线性光混合还会抬高明暗边缘的亮度。
新实现改用确定性的、归一化分离式高斯核，并在编码 sRGB、预乘 Alpha 空间内滤波。
依据是 [CSS Filter Effects 的 blur 定义与滤镜颜色空间要求](https://www.w3.org/TR/filter-effects-1/#funcdef-filter-blur)。

正文共享纹理继续使用 `SRGB8_ALPHA8`，保持 HTML-in-Canvas、Rito 和正文显示的既有契约。
进入模糊管线时才转成 `RGBA8`：先编码、预乘，再插值；直接把 sRGB framebuffer blit 到 RGBA framebuffer 会解码颜色，不能用于这一转换。

## 成本控制

- 按局部 σ 与 DPR 分区，使用 1×、½、¼、⅛ 等分辨率，工作核的标准差约为 2–4 texel。较粗一级的 σ 从 2 降到 1.5 texel 时平滑切换至下一档；混合区内细一级的 σ 为 3–4 texel，仍在采样上限内。相邻分区保留混合区及 3σ 邻域。
- 横纵分离并合并相邻双线性采样，17 个离散 texel 至多需 9 次读取 / 轴。次数是每个工作 texel 的上限，不是每个屏幕像素的总读取数。
- 各分区共享逐级 2× 降采样；偶数尺寸直接 blit，奇数尺寸用至多 4 次双线性读取积分源像素覆盖面积，避免普通缩放把高频细线混叠成明暗条带。卷积方差扣除降采样与线性重建已经引入的近似方差。
- 固定半径图片的权重只在参数变化时计算，使用 uniform 数组提交。原始分辨率时将纵向卷积合入最终输出，省去一张中间结果的写入和一次绘制。
- 纹理与参数不变时复用已完成的卷积。跨分辨率档位只在 GPU 内重建图集；没有 CPU 图像读回、时间累积降噪、固定帧率轮询或新的源图片上传。
- `compact9` 保持中心加四组双线性采样（9 次有效采样），仅在渐变半径的权重递推中用范围缩减的五阶多项式近似 `exp(-x)`，不再减少采样数。该路径仍是实验项，需在不同 GPU 上实测 shader 指令收益和误差。

`atlasBytes` / `savedRatio` 仍只统计打包后的图集。实际工作存储还包含降采样缓存、第一次卷积结果，以及未融合输出时的第二次结果；这些缓存复用并在 renderer 销毁时释放。更精确的卷积有中间存储和绘制调度成本，不能把“每轴 9 次”理解为成本与旧单 pass 完全相同。

## 渐变拉丝与接缝修正

σ 只随纵向位置变化时，卷积顺序应为先 Y、再 X。横向采样共享同一目标行，因此两轴使用相同的 σ；如果先 X 再 Y，纵向会读到其他行按不同 σ 模糊的结果，文字竖笔画会被异常拉长。
这一修正不增加采样或绘制次数。固定半径不受顺序约束，继续使用原有融合输出路径。

图集的裁切范围和输出坐标统一对齐到降采样金字塔的实际纹素网格，包含奇数尺寸和底部镜像。打包时复制相同数量的纹素，避免分别取整后再拉伸造成相位偏差。
分界使用连续半径曲线，过渡宽度跟随 σ，避免各档位都挤在固定 2px 内交接；降采样覆盖面积滤波同时消除不同档位的亮度偏差。

2026-09-08，在 718 × 176px 的深色标题测试中，以全分辨率、逐目标行计算相同 σ 的二维高斯为参考：28px 的 RGB MAE 从 0.432 降到 0.063，48px 从 1.400 降到 0.168。
标题上移 40px、跨越其他分区后，28px 的最大通道偏差从 16 降到 3。另用 719px 奇数宽的单像素交替细线检查降采样条带，修正后内部灰度均匀。
这些是指定测试图案的结果；贴近捕获范围外缘时，降采样后的边界延展仍可能与全分辨率参考不同。

## 图像验证

2026-09-08，Edge 152，DPR 1 / 2。两侧使用演示照片相同的源像素、512 × 342 CSS px 裁切和 145px 边缘延展。
参考是浏览器实际合成的 CSS `blur()`；对输出截图计算 RGB 平均绝对误差（MAE，通道满量程 255），排除画框外缘 16 CSS px。

| σ（CSS px） | 旧算法 MAE，DPR 1 | 新算法 MAE，DPR 1 | 新算法 MAE，DPR 2 |
| ----------- | ----------------- | ----------------- | ----------------- |
| 1           | 2.131             | 0.005             | < 0.001           |
| 4           | 5.097             | < 0.001           | 0.133             |
| 12          | 8.359             | 0.270             | 0.288             |
| 24          | 10.898            | 0.298             | 0.303             |
| 48          | 14.023            | 0.348             | 0.361             |

12px 的照片误差下降约 97%。黑白垂直边缘在 12px、DPR 1 下测得的单轴标准差为：旧算法 6.23px，新算法 11.96px，CSS 参考 11.88px；新实现沿平直边缘的逐行颗粒差为 0。48px 下仍有少量 8-bit 量化差，不能据此声称所有像素与 CSS 完全一致。

同时测试了 0、0.5、1、2、4、8、12、24、48px。零半径恢复原图；切换原图、尺寸变化、移动布局、WebGL 不可用与上下文恢复通过浏览器验证。连续修改三次半径时源纹理上传次数为 0；空闲时没有新增绘制。

## 性能样本与边界

2026-09-08，Apple M4、ANGLE Metal、Edge 152。使用 802 × 632 CSS px 的完整工作面（含照片边缘延展）、DPR 2，预热后采集 9 批、每批 12 帧。
每帧改变源 Canvas 的一个像素，再执行源纹理上传、图集准备和绘制；时间使用 `EXT_disjoint_timer_query_webgl2`，拒绝 disjoint 结果。

| σ    | 旧算法 GPU ms / 帧 | 新算法 GPU ms / 帧 |
| ---- | ------------------ | ------------------ |
| 12px | 1.58               | 0.83               |
| 28px | 3.00               | 0.67               |
| 48px | 4.84               | 0.68               |

这是一次本机内容更新工作负载的样本，不是跨设备保证，也不是 DOM 捕获耗时。只改半径、复用源纹理时，新高斯卷积在部分半径会比旧单 pass 慢；例如同次测量 1px、DPR 2 为 1.01ms 对 0.39ms。选择这一方案是为了显著减少与 CSS 的差异，同时把大半径工作限制在更小的纹理上。

纵向渐变按 Y → X 顺序可保持每个目标位置的核一致；实际管线仍使用有限核、降采样和 8-bit 中间存储。浏览器的高斯近似、边界延展与颜色量化也可能造成差异。当前定量结果覆盖 0–48px 和 DPR 1 / 2，未宣称其他浏览器或任意半径逐像素一致。
