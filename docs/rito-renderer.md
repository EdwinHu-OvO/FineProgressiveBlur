# Rito Canvas 后端

在演示页选择 **Rito Canvas + WebGL**，或设置
`<GradientBlurProvider captureBackend="rito">`。
自动模式优先 HTML-in-Canvas，不可用或失败后使用 Rito；只有无法创建 WebGL2 上下文时才使用 CSS。

## 渲染路径

1. `dom-scene.ts` 读取原生 DOM 布局、Computed Style、文字 Range 和资源，生成 Rito 绘制指令。
   CSS 排版仍由浏览器完成，因此现有 Flex/Grid 的位置不需要用另一套排版引擎重新计算。
2. `scene-tiles.ts` 使用提取的 Canvas 2D 绘制器绘制 1024 物理像素高的内容块，上传到 GPU。
   小文档完整缓存；长文档按可见范围加载并淘汰最近最少使用的块。
3. `rito-scene.ts` 在 GPU 内将内容块裁剪到视口，再合成选区和键盘焦点。
4. 正文与 `SurfaceOverlay` 使用同一 WebGL2 上下文，视口纹理直接进入原有自适应采样图集和模糊 Shader。

这里不调用 SnapDOM、html2canvas，也不把完整 HTML 序列化成 SVG。
内联 **SVG 资源本身**会复制样式并解码为图片；它不是 HTML `foreignObject` 捕获。
Canvas 2D → GPU 的首次/变更上传仍然存在，不把这条路径称为严格零拷贝。

## 更新与资源边界

- 没有固定采样频率限制。事件合并到下一个动画帧，一次只处理一个异步帧，保留最新待处理内容。
- 空闲时不安排连续渲染循环。内容事件只触发绘制指令检查；非视觉属性变化不会上传或绘制。
- 缓存内普通滚动只更新 GPU 取样窗口，不重新读取 DOM、重画 Canvas 或上传内容块。
- 内容变更按绘制指令及继承状态判断受影响块；候选块再用 GPU 比较全部像素，相同则跳过视口/模糊更新。
  GPU 比较只返回异步布尔值，不向 CPU 读回图像。
- 选区和焦点只更新 GPU 矩形图层，不重画或上传正文。
- 嵌套滚动和 sticky 元素会改变缓存内的画面，因此需要更新相关块。
- 64 MiB 是内容块缓存的估算预算，包含双 RGBA 候选纹理及 R8 比较目标。
  总显存还包括视口、模糊图集、降采样目标与浏览器自身资源；Canvas 绘制使用一个可复用临时块。
- `refresh()` 会重建后端并重新检查绘制和资源，也可重试失败的初始化，适用于嵌入 Canvas 的命令式绘制或外部 CSSOM 变化。
  动态 Canvas 不会被自动轮询。GIF/APNG 等图片内部动画也不作为连续更新源。
- 后端切换、卸载和 WebGL context loss 会终止待处理任务、释放纹理及监听器并移除呈现 Canvas。

## 交互方式

原有 React DOM 不重建、不移走，位于呈现 Canvas 下方；Canvas 设置 `pointer-events:none`，
真实滚轮、鼠标、触摸、按钮点击、链接默认行为、键盘和屏幕阅读器仍由浏览器处理。
它是布局与交互来源，并非另一个需要同步事件的 DOM 副本。
这保留了浏览器布局及可能的底层 DOM 绘制成本。

选区矩形从真正的文本 Range 投影到内容坐标，经 Rito 的合并逻辑处理后绘制到 GPU 视口。
复制仍使用浏览器的原生选区和快捷键；不接管剪贴板，也不合成点击事件。
Canvas 选区样式是独立高亮层，不承诺与浏览器的所有 `::selection` 样式逐像素一致。

## 当前支持范围

支持普通文本、浏览器提供的横向排版/换行、纯色背景、统一圆角边框、外阴影、
图片 `object-fit`、简单 URL 背景、自包含静态 SVG、按钮/链接和滚动容器。
文字与 DOM 的像素仍可能因字体度量、抗锯齿和小数位置产生细微差异。

遇到 transform、filter、mask、复杂背景、inset 阴影、生成内容、列表标记、
纵向/显式 RTL 排版、嵌入输入控件、iframe、video、Shadow DOM、SVG `foreignObject` 或
SMIL 动画时，保留原生正文并报告不可用状态，避免遮住 DOM 后显示不完整内容；不会转用 CSS 模糊。
根源需为 Provider 内的 HTML 容器，嵌入 Canvas 通过资源绘制接入。
源或祖先需提供明确的不透明纯色底色；透明层会逐层合成到这层底色。
错误原因写入 Provider 的 `data-rito-error`，演示页显示纹理后端不可用状态。

这是一条受限绘制后端，不是浏览器全部 HTML/CSS 的替代品。

2026-09-07 在独立的 Edge 152 / SwiftShader 浏览器中检查：

- 演示文档 DPR 2：连续 7 次滚动，正文 Canvas 重绘与 GPU 上传均为 0；GPU 视口绘制 7 次，两个模糊层合计 14 次。
- 空闲与非视觉属性修改：上传、视口绘制、模糊绘制均为 0。
- 选区变化：0 正文上传，1 次视口合成及两个模糊层更新，原生选区文本正确。
- 按钮切换保存状态、跨后端节点/状态保留、390px 窄屏、未支持滤镜回退均通过。
- DPR 1 / 1.5 / 2：内容尾块增高/缩短、50,000px 长文档缓存淘汰与往返、嵌套滚动、嵌入 Canvas 手动刷新、context loss 均通过；采样色块与预期 RGB 完全一致。
- 零半径画面对比：DPR 2 的演示视口 RGB 平均绝对差约 0.74/255；这不是所有 HTML 的兼容性保证。
- 单元测试覆盖队列合并/取消、缓存块内容判定、跨栏选区合并，以及原有采集、像素比较和 CSS 模糊测试。
